# Entitlements

## `client.Entitlements.ReadSubscriptionEntitlements` — `GET /subscriptions/{subscription_id}/entitlements.json` (`readSubscriptionEntitlements`)

- **silent**, -/lists: Several products/components grant the same feature, or a usage_limit feature is granted with different periodicities → Entitlements are collapsed into one entry per feature key and periodicity window; different periodicities come back as separate entries sharing one feature_key.. **Do:** Key entitlements by periodicity_key, not by feature_key. *(spec `spec/openapi.yaml`; spec `spec/components/schemas/Aggregated-Entitlement.yaml`; docs `content/introduction/basic-concepts/entitlements.md`; `maxio-c4:readSubscriptionEntitlements.1`)*
- **silent**, -/values: An aggregated entitlement has a periodicity window → periodicity_key is the prefixed feature key suffixed with :{interval}:{unit}; it equals feature_key when periodicity is null.. **Do:** Use periodicity_key as the unique id of an entry. *(spec `spec/components/schemas/Aggregated-Entitlement.yaml`; `maxio-c4:readSubscriptionEntitlements.10`)*
- **silent**, -/values: Several products or components on a subscription grant the same feature → Entitlements are collapsed into one entry per feature key and periodicity window, so different periodicities give separate entries with their own periodicity_key.. **Do:** Key entitlements by periodicity_key, not only by feature_key. *(docs `content/introduction/basic-concepts/entitlements.md`; `maxio-c4:readSubscriptionEntitlements.101`)*
- **silent**, state/values: The subscription is not in a live state (active, trialing, assessing, past_due or soft_failure) → enabled is false regardless of the aggregated value; entitlements stay enabled while the subscription is in dunning.. **Do:** Check enabled before granting access in your application. *(docs `content/introduction/basic-concepts/entitlements.md`; spec `spec/openapi.yaml`; `maxio-c4:readSubscriptionEntitlements.102`)*
- **silent**, -/values: More than one contributor grants the same access_right feature key and periodicity → Values are combined with boolean OR: true if any contributor grants access; source_products lists only contributors that granted true.. **Do:** Treat an access_right as granted when any product or component grants it. *(spec `spec/openapi.yaml`; `maxio-c4:readSubscriptionEntitlements.2`)*
- **silent**, -/values: More than one contributor grants the same usage_limit feature key → Values are summed across contributors sharing the same periodicity window; grants with different periodicities are not summed and are returned as separate entries.. **Do:** Read the summed limit per periodicity_key; do not add entries of different periodicities yourself. *(spec `spec/openapi.yaml`; `maxio-c4:readSubscriptionEntitlements.3`)*
- **silent**, -/values: More than one contributor grants the same service_right feature key → Values are not combined; one contributor's value wins, and which one is not defined.. **Do:** Avoid granting the same service_right key from several products/components, or do not depend on which value is returned. *(spec `spec/openapi.yaml`; `maxio-c4:readSubscriptionEntitlements.4`)*
- **silent**, state/values: The subscription is not in a live state (active, trialing, assessing, past_due, soft_failure), e.g. awaiting_signup, canceled, expired or on hold → enabled is false for every entitlement, regardless of the aggregated value.. **Do:** Check enabled, not value, before granting access in your application. *(spec `spec/openapi.yaml`; spec `spec/components/schemas/Aggregated-Entitlement.yaml`; docs `content/introduction/basic-concepts/entitlements.md`; `maxio-c4:readSubscriptionEntitlements.5`)*
- **silent**, state/values: The subscription is in dunning (past_due or soft_failure) → Entitlements stay enabled through dunning.. **Do:** Do not expect entitlements to switch off while the subscription is in dunning; restrict access yourself if your policy requires it. *(spec `spec/openapi.yaml`; docs `content/introduction/basic-concepts/entitlements.md`; `maxio-c4:readSubscriptionEntitlements.6`)*
- **silent**, -/values: The aggregated value is not truthy for the feature's kind (for example false or 0) → enabled is false even when the subscription is live.. **Do:** Check enabled rather than the presence of an entry. *(spec `spec/components/schemas/Aggregated-Entitlement.yaml`; `maxio-c4:readSubscriptionEntitlements.7`)*
- **silent**, -/values: An aggregated entitlement is returned → value is coerced by type: boolean for access_right (and boolean service_right), number for usage_limit (and numeric service_right), string for text service_right.. **Do:** Parse value according to type rather than as the string stored on the feature catalog item. *(spec `spec/components/schemas/Aggregated-Entitlement.yaml`; `maxio-c4:readSubscriptionEntitlements.8`)*
- **silent**, -/values: An aggregated entitlement is returned → feature_key is the template key prefixed by kind: feature.* for access_right, usage.* for usage_limit, service.* for service_right.. **Do:** Match entitlements on the prefixed key (e.g. feature.sso), not the bare template key. *(spec `spec/components/schemas/Aggregated-Entitlement.yaml`; `maxio-c4:readSubscriptionEntitlements.9`)*
