# Product Features

## `client.ProductFeatures.CreateProductFeature` — `POST /products/{product_id}/features.json` (`createProductFeature`)

- **loud**, -/errors: The request body of a feature catalog item create names the owning product or component → 422. **Do:** Leave the owning product or component out of the body; it comes from the URL. Also: `createComponentFeature`. *(spec `spec/components/schemas/Create-Feature-Catalog-Item-Request.yaml`; `maxio-c4:createProductFeature.1`)*
- **loud**, -/errors: Only one of price_point_type and price_point_id is sent when creating a feature catalog item → 422. **Do:** Send price_point_type and price_point_id together to scope an override, or neither. Also: `createComponentFeature`. *(spec `spec/components/schemas/Create-Feature-Catalog-Item-Request.yaml`; spec `spec/components/schemas/Feature-Owner-Price-Point-Type.yaml`; `maxio-c4:createProductFeature.2`)*
- **silent**, order/side-effects: A feature is attached to a product or component that subscribers already have → Subscribers are provisioned the entitlement automatically only the next time their subscription changes (for example signup, plan change or component allocation). **Do:** Do not expect existing subscribers to get a new feature until their subscription next changes. Also: `background:entitlement-provisioning`, `createComponentFeature`. *(docs `content/introduction/basic-concepts/entitlements.md`; `maxio-c4:background.72`)*
- **silent**, -/values: A feature catalog item is created without price_point_type → The item applies to every price point of the product or component. **Do:** Omit price_point_type and price_point_id for a product-wide feature. Also: `createComponentFeature`. *(spec `spec/components/schemas/Create-Feature-Catalog-Item-Request.yaml`; `maxio-c4:createProductFeature.3`)*
- **silent**, -/side-effects: A feature catalog item is created without propagate_to_subscriptions=true → Existing subscribers on the product or component get the entitlement only at their next subscription change (signup, plan change, component allocation). **Do:** Send propagate_to_subscriptions=true when existing subscribers must get the feature now. Also: `createComponentFeature`. *(docs `content/introduction/basic-concepts/entitlements.md`; spec `spec/components/schemas/Create-Feature-Catalog-Item-Request.yaml`; `maxio-c4:createProductFeature.4`)*
- **silent**, -/side-effects: A feature catalog item is created with propagate_to_subscriptions=true → Existing subscriptions on the product or component are granted the entitlement immediately. **Do:** Check subscriptions_count on the list response before propagating to many subscriptions. Also: `createComponentFeature`. *(spec `spec/components/schemas/Create-Feature-Catalog-Item-Request.yaml`; `maxio-c4:createProductFeature.5`)*

## `client.ProductFeatures.UpdateProductFeature` — `PUT /products/{product_id}/features/{id}.json` (`updateProductFeature`)

- **silent**, -/side-effects: A component or product feature catalog item is updated with propagate_to_subscriptions true → The new value/periodicity is applied immediately to every existing entitlement created from the item. **Do:** Send propagate_to_subscriptions=true only when existing entitlements must change now; check subscriptions_count first to see how many subscriptions it touches. Also: `updateComponentFeature`. *(spec `spec/components/schemas/Update-Feature-Catalog-Item-Request.yaml`; `maxio-c4:updateComponentFeature.1`)*

## `client.ProductFeatures.RemoveProductFeature` — `DELETE /products/{product_id}/features/{id}.json` (`removeProductFeature`)

- **silent**, -/side-effects: A component feature catalog item is removed with destroy_entitlements=true → The item and every entitlement it created are permanently deleted and subscriber access is revoked immediately. **Do:** Use destroy_entitlements=true only when immediate, permanent revocation is intended. Also: `removeComponentFeature`. *(spec `spec/openapi.yaml`; docs `content/introduction/basic-concepts/entitlements.md`; spec `spec/openapi.yaml`; `maxio-c4:removeComponentFeature.2`)*
- **silent**, -/side-effects: A feature catalog item is removed without destroy_entitlements=true → Removal is soft: the feature leaves the catalog but subscribers who already have it keep their entitlement. **Do:** Pass destroy_entitlements=true when access must be revoked immediately. Also: `removeComponentFeature`. *(docs `content/introduction/basic-concepts/entitlements.md`; `maxio-c4:removeProductFeature.101`)*
- **silent**, -/side-effects: A feature catalog item is removed without destroy_entitlements (or with false) → The item is archived and subscribers who already have the entitlement keep it. **Do:** Expect existing subscribers to keep the feature after a default removal. Also: `removeComponentFeature`. *(spec `spec/openapi.yaml`; docs `content/introduction/basic-concepts/entitlements.md`; `maxio-c4:removeProductFeature.2`)*

## `client.ProductFeatures.RestoreProductFeature` — `POST /products/{product_id}/features/{id}/restore.json` (`restoreProductFeature`)

- **loud**, state/errors: restoreProductFeature is called while the item's parent feature template is still archived → 422. **Do:** Restore the feature template first, then the product feature catalog item. *(spec `spec/openapi.yaml`; `maxio-c4:restoreProductFeature.1`)*
