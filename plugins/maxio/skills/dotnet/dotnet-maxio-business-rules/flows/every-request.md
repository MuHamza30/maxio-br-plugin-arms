# Every request

- **loud**, auth/- (`*`): Any API request is made → outcome not stated. **Do:** Authenticate every request with HTTP Basic over HTTPS, using the site API key as the username and x as the password. *(`maxio-c4:every-request.1`)*
- **loud**, auth/- (`*`): A request is authenticated with the username and password used to log in to the web interface → outcome not stated. **Do:** Obtain API credentials (API keys) separately and never use web login credentials for API calls. *(`maxio-c4:every-request.2`)*
- **loud**, limits/errors (`*`): Too many requests are slowed or the account queue is full of concurrent requests → 429 "Your request was denied due to a usage violation. You can track this request with support by referencing …". **Do:** On 429, pause requests for a few minutes and then continue more slowly or with less concurrency. *(`maxio-c4:every-request.28`)*
- **loud**, other/- (`*`): A client connects with TLS 1.0 or TLS 1.1 → Clients that do not support TLS 1.2 no longer work.. **Do:** Connect with TLS 1.2 or newer. *(`maxio-c4:every-request.3`)*
- **loud**, limits/- (`*`): A request (including the time spent at the payment gateway) is not processed within 120 seconds → The request times out.. **Do:** Allow for the 120-second cut-off, and after a timeout check the gateway status and retry safely with a uniqueness_token. *(`maxio-c4:every-request.31`)*
- **loud**, account-config/errors (`*`): The merchant's Advanced Billing subscription is canceled → 422 "Your Advanced Billing account has been canceled. Please contact support@maxio.com to reactivate.". **Do:** Treat this 422 as an account block, not a request validation error, and contact Maxio support. *(`maxio-c4:every-request.32`)*
- **loud**, account-config/errors (`*`): The merchant's Advanced Billing trial has ended → 422 "Your trial has ended, please contact sales.". **Do:** Treat this 422 as an account block and contact Maxio sales. *(`maxio-c4:every-request.33`)*
- **loud**, state/errors (`*`): The site being called is in the process of clearing site data (requests to other sites in a good state are not blocked) → 422 "Site data clearing is in progress. Please try later.". **Do:** Wait until site data clearing finishes before calling that site again. *(`maxio-c4:every-request.34`)*
- **loud**, state/errors (`*`): The site being called has been deleted → 422 "This site has been deleted.". **Do:** Stop calling a deleted site and point the integration at a live site. *(`maxio-c4:every-request.35`)*
- **loud**, idempotency/errors (`*`): A POST, PUT, PATCH or DELETE request carries a top-level uniqueness_token already used by an earlier request → 409 "DuplicatePrevention::DuplicateSubmissionError". **Do:** Send a long random uniqueness_token (such as a UUID) at the top level of every data-changing request you may retry. *(`maxio-c4:every-request.36`)*
- **loud**, idempotency/errors (`*`): A request with a uniqueness_token was received but failed (for example with 422), and is retried with the same token → 409 "DuplicatePrevention::DuplicateSubmissionError" The token was spent when the first request was received, whether or not it succeeded.. **Do:** Generate a new uniqueness_token before retrying a corrected request. *(`maxio-c4:every-request.38`)*
- **loud**, idempotency/other (`*`): A retried request is rejected with 409 because its uniqueness_token was already used → 409 The API does not store or replay the original response; the 409 shows only that the first request arrived, not whether it succeeded.. **Do:** After a 409, confirm the first request's outcome by reading the resource or matching webhooks before deciding to retry. *(`maxio-c4:every-request.39`)*
- **loud**, auth/errors (`*`): An API request is made directly from a customer's browser or device → "Response to preflight request doesn't pass access control check: No 'Access-Control-Allow-Origin' header is present on the requested resource." CORS is not supported and cannot be enabled, and a client-side call would expose the API key.. **Do:** Make API calls only from your server; tokenize card data in the browser with Maxio.js. *(`maxio-c4:every-request.41`)*
- **loud**, account-config/errors (`*`): A subscription's payment_collection_method is set to a value not valid for the site's architecture → Statement-based sites accept automatic or invoice; Relationship Invoicing sites accept automatic, remittance or prepaid.. **Do:** Choose payment_collection_method from the values valid for the site's architecture. *(`maxio-c4:every-request.42`)*
- **loud**, state/- (`*`): A subscription that holds any active wallet (manual or provisioned) is switched to prepaid collection → outcome not stated. **Do:** Archive the subscription's wallets before moving it to prepaid collection, or keep it off prepaid. *(`maxio-c4:every-request.44`)*
- **loud**, other/errors (`*`): A POST or PUT request sends its data as query parameters or form-encoded data, or without a Content-Type of application/json or application/xml → The data is not accepted and the request may fail because forgery protection is triggered.. **Do:** Send POST and PUT bodies as JSON or XML with a matching Content-Type header. *(`maxio-c4:every-request.7`)*
- **silent**, -/values (`*`): An individual statement or invoice is fetched with Accept application/pdf or a .pdf extension → The document is returned as a PDF.. **Do:** Use application/pdf or .pdf only on GETs for individual statements and invoices. *(`maxio-c4:every-request.10`)*
- **silent**, -/values (`*`): A boolean field in a response is null → null may mean false, but not in every case; it can also mean no data is available.. **Do:** Do not map null booleans to false blindly; treat null as unknown unless the field's meaning says otherwise. *(`maxio-c4:every-request.11`)*
- **silent**, -/values (`*`): A response contains timestamp fields → Timestamps are in the site's time zone, ISO 8601 with a UTC offset and no fractional seconds.. **Do:** Parse timestamps with their offset and do not assume UTC. *(`maxio-c4:every-request.12`)*
- **silent**, -/values (`*`): A response contains date-only fields (for example issue_date, due_date, paid_date) → They are YYYY-MM-DD strings giving the site's local calendar date, not the UTC date.. **Do:** Treat date-only fields as site-local dates without converting them through UTC. *(`maxio-c4:every-request.13`)*
- **silent**, -/values (`*`): A request sends a date without a time → The API uses noon in the site's time zone.. **Do:** Send a full timestamp with offset when a time other than noon in the site's time zone is meant. *(`maxio-c4:every-request.14`)*
- **silent**, -/values (`*`): A request sends a date and time without a time zone offset → The time of day is taken in the site's time zone.. **Do:** Add a UTC offset to request timestamps unless site-local time is intended. *(`maxio-c4:every-request.15`)*
- **silent**, -/values (`*`): A request sends a date, time and time zone offset → The API uses that absolute instant and shows it back in the site's time zone.. **Do:** Compare returned timestamps as instants, since they come back in the site's time zone rather than the zone you sent. *(`maxio-c4:every-request.16`)*
- **silent**, -/values (`*`): A response contains decimal numbers → Decimal numbers are serialized as strings to avoid losing precision.. **Do:** Parse decimal strings with a decimal library, not floating point. *(`maxio-c4:every-request.17`)*
- **silent**, -/values (`*`): A response contains amount fields → Top-level totals (such as total_amount, tax_amount) are rounded to the currency's smallest unit, but line-item unit_price and quantity can carry more decimal places.. **Do:** Do your own rounding where needed and do not assume every amount is rounded to the currency's minor unit. *(`maxio-c4:every-request.18`)*
- **silent**, -/values (`*`): A resource (such as an invoice or credit note) exposes both a numeric id and a string uid → The uid is a separate opaque identifier and is not interchangeable with the numeric id.. **Do:** Use id or uid exactly where each is asked for and never substitute one for the other. *(`maxio-c4:every-request.19`)*
- **silent**, -/other (`*`): Maxio adds endpoints, response attributes, optional parameters or export fields → Such backwards-compatible changes are made without advance notice.. **Do:** Ignore unknown response attributes and export fields instead of failing on them. *(`maxio-c4:every-request.20`)*
- **silent**, -/values (`*`): An ID attribute is stored or parsed by the client → The type or length of ID attributes may change without notice; most are integers today.. **Do:** Store IDs in a type that does not assume a fixed integer size or type. *(`maxio-c4:every-request.21`)*
- **silent**, -/values (`*`): A client reads attributes from an API response → The order of attributes in a response may change.. **Do:** Read response attributes by name, never by position. *(`maxio-c4:every-request.22`)*
- **silent**, -/lists (`*`): A list endpoint that uses the standard per_page parameter is called without per_page or with per_page above 200 → Usually 20 items are returned by default; a per_page above 200 is changed to 200.. **Do:** Page through lists with page and per_page (at most 200) instead of expecting everything in one response. *(`maxio-c4:every-request.23`)*
- **silent**, -/lists (`*`): A list endpoint is asked for a page beyond the last page of results → An empty result set is returned rather than an error.. **Do:** Stop paging when a page comes back empty. *(`maxio-c4:every-request.24`)*
- **silent**, -/lists (`*`): A list request sends a date_field value other than created_at or updated_at → The value is ignored and the date filters are not applied, so unfiltered records are returned.. **Do:** Send only date_field values the endpoint supports and check that results are actually filtered. *(`maxio-c4:every-request.25`)*
- **silent**, limits/- (`*`): More than 4 API calls run at the same time for one subdomain → Calls above the 4-call concurrency limit may be queued until concurrency drops.. **Do:** Limit the integration to 4 concurrent requests per subdomain. *(`maxio-c4:every-request.26`)*
- **silent**, limits/- (`*`): A large synchronization or burst of requests trips the rate-based failsafe → Requests are slowed and throttled instead of being rejected at once.. **Do:** When responses slow down, do not add parallel requests; reduce concurrency. *(`maxio-c4:every-request.27`)*
- **silent**, limits/- (`*`): Low-priority requests (reports and exports) arrive while the system is balancing load → Critical endpoints such as new signups and component allocations are favoured, and reports and exports are slowed down.. **Do:** Expect report and export calls to be slower under load and schedule them away from critical traffic. *(`maxio-c4:every-request.29`)*
- **silent**, limits/- (`*`): Many simultaneous requests go to the same endpoint, or to an expensive endpoint → Expensive endpoints have lower limits, and simultaneous requests to the same endpoint are queued behind each other.. **Do:** Spread requests over time instead of sending many at once to the same endpoint. *(`maxio-c4:every-request.30`)*
- **silent**, idempotency/- (`*`): A uniqueness_token is reused more than 60 minutes after it was first sent → Tokens are kept for a minimum of 60 minutes only, so later reuse may not be detected as a duplicate.. **Do:** Retry within the retention window, or confirm the outcome by reading the resource before retrying later. *(`maxio-c4:every-request.37`)*
- **silent**, other/- (`*`): A request uses different letter case in a path, parameter or value than documented → The API is case-sensitive, so differently cased names are not treated as the same.. **Do:** Use the exact case shown in the reference for paths, parameter names and values. *(`maxio-c4:every-request.4`)*
- **silent**, idempotency/- (`*`): The same uniqueness_token is sent with a different API key or to a different site → It is not treated as a duplicate, because tokens are scoped to the site and the API credentials.. **Do:** Send retries with the same API key and site as the original request. *(`maxio-c4:every-request.40`)*
- **silent**, account-config/values (`*`): Subscribers are to be taxed through Avalara or custom taxes → A subscriber is taxed only with a taxable product, a full valid billing or shipping address, a 2-3 character ISO state and a 2 character ISO country on the customer or payment profile.. **Do:** Collect full addresses with ISO state and country codes for subscribers who must be taxed. *(`maxio-c4:every-request.43`)*
- **silent**, account-config/other (`*`): The site has the new catalog experience enabled → Only UI labels change (Products become Plans, Components become Products); API object names and endpoints stay the same.. **Do:** Map UI Plans to API products and UI Products to API components. *(`maxio-c4:every-request.45`)*
- **silent**, account-config/- (`*`): The Advanced Billing account is hosted in the EU environment → The EU environment is served from https://{site}.ebilling.maxio.com instead of https://{site}.chargify.com.. **Do:** Use the EU host only when EU hosting was requested for the account, and the US host otherwise. *(`maxio-c4:every-request.6`)*
- **silent**, -/values (`*`): A request is sent with a Content-Type or Accept header, or a .json or .xml extension on the resource URI → The response is JSON or XML according to the header or extension; JSON is the primary format and XML a backwards-compatible option.. **Do:** Ask for JSON explicitly with the .json extension and Accept/Content-Type application/json. *(`maxio-c4:every-request.8`)*
- **silent**, -/errors (`*`): A request is sent without a .json or .xml format extension → An error may come back as an HTML page instead of the documented error body.. **Do:** Request the .json (or .xml) format on every call so errors are machine-readable. *(`maxio-c4:every-request.9`)*
