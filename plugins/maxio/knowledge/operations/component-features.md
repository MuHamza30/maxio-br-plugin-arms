## `client.ComponentFeatures.CreateComponentFeature` — `POST /components/{component_id}/features.json` (`createComponentFeature`)

- **loud**, other/-: The create request body names the owning product or component → outcome not stated. **Do:** Leave the owning component out of the body; the server takes it from the URL. *(spec `spec/components/schemas/Create-Feature-Catalog-Item-Request.yaml`; `maxio-c4:createComponentFeature.1`)*
- **loud**, other/-: Only one of price_point_type and price_point_id is sent → outcome not stated. **Do:** Send price_point_type and price_point_id together, or neither. *(spec `spec/components/schemas/Create-Feature-Catalog-Item-Request.yaml`; spec `spec/components/schemas/Feature-Catalog-Item.yaml`; `maxio-c4:createComponentFeature.3`)*
- **loud**, other/-: A component feature override is scoped to a price point with a price_point_type other than PricePoint → outcome not stated. **Do:** Use price_point_type "PricePoint" (a component price point) for component overrides; ProductPricePoint is for products. *(spec `spec/openapi.yaml`; spec `spec/components/schemas/Feature-Owner-Price-Point-Type.yaml`; `maxio-c4:createComponentFeature.4`)*
- **loud**, other/-: The feature value does not fit the feature template's kind ("true"/"false" for access_right, a numeric string for usage_limit) → outcome not stated. **Do:** Send value as "true"/"false" for access_right, a numeric string for usage_limit, and a string shaped by value_type for service_right. Also: `updateComponentFeature`. *(spec `spec/components/schemas/Feature-Catalog-Item.yaml`; `maxio-c4:createComponentFeature.6`)*
- **loud**, -/errors: The request body of a feature catalog item create names the owning product or component → 422. **Do:** Leave the owning product or component out of the body; it comes from the URL. - **loud**, -/errors: Only one of price_point_type and price_point_id is sent when creating a feature catalog item → 422. **Do:** Send price_point_type and price_point_id together to scope an override, or neither. - **silent**, order/side-effects: A feature is attached to a product or component that subscribers already have → Subscribers are provisioned the entitlement automatically only the next time their subscription changes (for example signup, plan change or component allocation).. **Do:** Do not expect existing subscribers to get a new feature until their subscription next changes. - **silent**, -/values: A component feature catalog item is created without price_point_type (and price_point_id) → The item applies to every price point of the component.. **Do:** Send price_point_type and price_point_id only when the feature must be scoped to one component price point. *(spec `spec/components/schemas/Create-Feature-Catalog-Item-Request.yaml`; spec `spec/components/schemas/Feature-Catalog-Item.yaml`; `maxio-c4:createComponentFeature.2`)*
- **silent**, -/side-effects: A feature is attached to a component without propagate_to_subscriptions (default false) → Existing subscriptions on the component get the entitlement only at their next subscription change (signup, plan change or component allocation), not immediately.. **Do:** Send propagate_to_subscriptions=true when existing subscribers must get the feature now. *(spec `spec/components/schemas/Create-Feature-Catalog-Item-Request.yaml`; docs `content/introduction/basic-concepts/entitlements.md`; `maxio-c4:createComponentFeature.5`)*
- **silent**, -/values: The feature template's kind is not usage_limit → periodicity_interval and periodicity_unit are null on the feature catalog item.. **Do:** Send a periodicity only for usage_limit features and expect null periodicity for the other kinds. - **silent**, -/values: A feature catalog item is created without price_point_type → The item applies to every price point of the product or component.. **Do:** Omit price_point_type and price_point_id for a product-wide feature. Also: `createProductFeature`. *(spec `spec/components/schemas/Create-Feature-Catalog-Item-Request.yaml`; `maxio-c4:createProductFeature.3`)*
- **silent**, -/side-effects: A feature catalog item is created without propagate_to_subscriptions=true → Existing subscribers on the product or component get the entitlement only at their next subscription change (signup, plan change, component allocation).. **Do:** Send propagate_to_subscriptions=true when existing subscribers must get the feature now. ## `client.ComponentFeatures.RemoveComponentFeature` — `DELETE /components/{component_id}/features/{id}.json` (`removeComponentFeature`)

- **silent**, -/side-effects: A component feature catalog item is removed without destroy_entitlements (default false) → The item is archived and existing subscribers keep their entitlement (grandfathered).. **Do:** Send destroy_entitlements=true if subscribers must lose the feature; otherwise expect existing entitlements to remain. *(spec `spec/openapi.yaml`; docs `content/introduction/basic-concepts/entitlements.md`; `maxio-c4:removeComponentFeature.1`)*
- **silent**, -/side-effects: A component feature catalog item is removed with destroy_entitlements=true → The item and every entitlement it created are permanently deleted and subscriber access is revoked immediately.. **Do:** Use destroy_entitlements=true only when immediate, permanent revocation is intended. Also: `removeProductFeature`. *(spec `spec/openapi.yaml`; docs `content/introduction/basic-concepts/entitlements.md`; spec `spec/openapi.yaml`; `maxio-c4:removeComponentFeature.2`)*
- **silent**, -/side-effects: A feature catalog item is removed without destroy_entitlements=true → Removal is soft: the feature leaves the catalog but subscribers who already have it keep their entitlement.. **Do:** Pass destroy_entitlements=true when access must be revoked immediately. Also: `removeProductFeature`. *(docs `content/introduction/basic-concepts/entitlements.md`; `maxio-c4:removeProductFeature.101`)*
- **silent**, -/side-effects: A feature catalog item is removed without destroy_entitlements (or with false) → The item is archived and subscribers who already have the entitlement keep it.. **Do:** Expect existing subscribers to keep the feature after a default removal. Also: `removeProductFeature`. *(spec `spec/openapi.yaml`; docs `content/introduction/basic-concepts/entitlements.md`; `maxio-c4:removeProductFeature.2`)*
