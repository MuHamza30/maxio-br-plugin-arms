## `client.WebhooksApi.ReplayWebhooks` — `POST /webhooks/replay.json` (`replayWebhooks`)

- **loud**, limits/-: A replay request lists more than 1000 webhook IDs → outcome not stated. **Do:** Send at most 1000 webhook IDs per replay request and split larger sets. *(spec `spec/openapi.yaml`; `maxio-c4:replayWebhooks.2`)*
- **silent**, idempotency/webhooks: A webhook is retried or replayed → The webhook keeps the same id across retries and replays, so the same event can arrive more than once with one id.. **Do:** Record processed webhook ids and skip ones already handled. Also: `background:webhook-delivery`, `listWebhooks`. *(spec `spec/components/schemas/Webhook.yaml`; docs `content/introduction/webhooks/webhooks-reference.md`; `maxio-c4:background.3`)*
- **silent**, limits/-: Webhook data is older than the site's webhook data retention limit → Advanced Billing stores webhook data only for a limited time (see Merchant Limits).. **Do:** Do not rely on old webhooks being available to list or replay; keep your own record of what you need. Also: `listWebhooks`. *(docs `content/introduction/webhooks/webhooks.md`; `maxio-c4:listWebhooks.2`)*
- **silent**, -/other: Replay Webhooks is accepted → The webhooks are not resent immediately; they are queued and sent as soon as system resources allow.. **Do:** Do not expect replayed webhooks to arrive at once; watch last_sent_at or your endpoint instead of the replay response. *(spec `spec/openapi.yaml`; `maxio-c4:replayWebhooks.1`)*
- **silent**, -/values: A webhook is explicitly replayed by the merchant → The webhook's accepted_at is cleared until the endpoint accepts it again.. **Do:** Do not treat a null accepted_at on a replayed webhook as a past delivery failure. *(spec `spec/components/schemas/Webhook.yaml`; `maxio-c4:replayWebhooks.3`)*
- **silent**, state/-: Paused webhooks reference an endpoint that has been deleted from Advanced Billing → Those paused webhooks cannot be resent and are effectively discarded.. **Do:** Replay or resend paused webhooks before deleting their endpoint. *(docs `content/introduction/webhooks/webhooks.md`; `maxio-c4:replayWebhooks.4`)*
- **silent**, idempotency/webhooks: Webhooks are replayed while the automatic retries for them may still be running → The same webhook can be delivered more than once (the replay and a retry).. **Do:** Track processed webhook IDs and replay only once last_sent_at is well outside the automatic retry intervals. *(docs `content/introduction/webhooks/webhooks.md`; docs `content/introduction/webhooks/webhooks.md`; `maxio-c4:replayWebhooks.5`)*

## `client.WebhooksApi.CreateEndpoint` — `POST /endpoints.json` (`createEndpoint`)

- **loud**, -/errors: An endpoint is created with a URL whose scheme is not http or https → 422 "URL: invalid, only http and https supported". **Do:** Give endpoint URLs an http or https scheme. *(spec `spec/openapi.yaml`; `maxio-c4:createEndpoint.1`)*
- **loud**, account-config/-: A webhook endpoint URL uses plain HTTP while the site is in live mode → outcome not stated. **Do:** Use an HTTPS endpoint URL before taking the site live. Also: `updateEndpoint`. *(docs `content/introduction/webhooks/webhooks.md`; `maxio-c4:createEndpoint.2`)*
- **loud**, limits/-: A site already has the maximum number of webhook endpoints allowed by its merchant limits → outcome not stated. **Do:** Check the site's endpoint limit (Merchant Limits) before adding endpoints and reuse existing ones. *(docs `content/introduction/webhooks/webhooks.md`; `maxio-c4:createEndpoint.4`)*
- **silent**, -/other: A webhook endpoint is hosted on a port other than 80 or 443 → Ports other than 80 and 443 are not supported.. **Do:** Host webhook endpoints on port 80 or 443. Also: `updateEndpoint`. *(docs `content/introduction/webhooks/webhooks.md`; `maxio-c4:createEndpoint.3`)*

## `client.WebhooksApi.UpdateEndpoint` — `PUT /endpoints/{endpoint_id}.json` (`updateEndpoint`)

- **loud**, account-config/-: A webhook endpoint URL uses plain HTTP while the site is in live mode → outcome not stated. **Do:** Use an HTTPS endpoint URL before taking the site live. Also: `createEndpoint`. *(docs `content/introduction/webhooks/webhooks.md`; `maxio-c4:createEndpoint.2`)*
- **loud**, -/errors: Update Endpoint names an event key that is not a valid webhook event → 422 "Event key is not valid - foobar". **Do:** Use only event keys from the Webhooks Reference event list. *(spec `spec/openapi.yaml`; `maxio-c4:updateEndpoint.3`)*
- **silent**, -/other: A webhook endpoint is hosted on a port other than 80 or 443 → Ports other than 80 and 443 are not supported.. **Do:** Host webhook endpoints on port 80 or 443. Also: `createEndpoint`. *(docs `content/introduction/webhooks/webhooks.md`; `maxio-c4:createEndpoint.3`)*
- **silent**, -/values: Update Endpoint is called with a webhook_subscriptions list → The list replaces the endpoint's subscribed events; any event left out is unsubscribed.. **Do:** Always send the complete list of events the endpoint should stay subscribed to. *(spec `spec/openapi.yaml`; spec `spec/openapi.yaml`; `maxio-c4:updateEndpoint.1`)*
- **silent**, -/values: Update Endpoint is called with an empty webhook_subscriptions list → The endpoint is unsubscribed from all events.. **Do:** Never send an empty webhook_subscriptions list unless you mean to unsubscribe every event. *(spec `spec/openapi.yaml`; `maxio-c4:updateEndpoint.2`)*
