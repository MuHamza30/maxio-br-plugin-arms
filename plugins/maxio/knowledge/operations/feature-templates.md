## `client.FeatureTemplates.CreateFeatureTemplate` — `POST /features.json` (`createFeatureTemplate`)

- **loud**, -/errors: A feature template is created with kind usage_limit and no unit → 422. **Do:** Send unit whenever kind is usage_limit. *(spec `spec/components/schemas/Create-Feature-Template-Request.yaml`; spec `spec/components/schemas/Feature-Template.yaml`; `maxio-c4:createFeatureTemplate.1`)*
- **loud**, -/errors: A feature template is created with kind service_right and no value_type → 422. **Do:** Send value_type (text, boolean or numeric) whenever kind is service_right. *(spec `spec/components/schemas/Create-Feature-Template-Request.yaml`; `maxio-c4:createFeatureTemplate.2`)*
- **loud**, -/errors: default_periodicity_interval or default_periodicity_unit is sent for a feature template whose kind is not usage_limit → 422. **Do:** Send default periodicity only for usage_limit templates. *(spec `spec/components/schemas/Create-Feature-Template-Request.yaml`; spec `spec/components/schemas/Feature-Template.yaml`; `maxio-c4:createFeatureTemplate.4`)*
- **loud**, -/errors: Only one of default_periodicity_unit and default_periodicity_interval is sent → 422. **Do:** Send default_periodicity_unit and default_periodicity_interval together or not at all. *(spec `spec/components/schemas/Create-Feature-Template-Request.yaml`; `maxio-c4:createFeatureTemplate.5`)*
- **loud**, other/errors: A feature template is created with a key that another feature template already uses → 422. **Do:** Choose a key not already used by any feature template on the site (archived ones included). *(spec `spec/components/schemas/Create-Feature-Template-Request.yaml`; `maxio-c4:createFeatureTemplate.6`)*
- **loud**, state/-: A feature template's key would be changed after it was set → outcome not stated. **Do:** Choose feature template keys carefully; create a new template instead of changing a key. Also: `updateFeatureTemplate`. *(docs `content/introduction/basic-concepts/entitlements.md`; `maxio-c4:updateFeatureTemplate.101`)*
- **silent**, account-config/side-effects: A Feature has wallet_behavior and a subscription resolves an entitlement to it → A wallet with origin feature is provisioned automatically; Create Wallet is never called for it. **Do:** Configure wallet_behavior on the Feature template instead of creating these wallets yourself. Also: `background:wallet-provisioning`, `updateFeatureTemplate`. *(docs `content/introduction/basic-concepts/wallets.md`; `maxio-c4:background.74`)*
- **silent**, -/values: A feature template of kind access_right or usage_limit is created with a value_type → value_type is ignored and set automatically: boolean for access_right, numeric for usage_limit. **Do:** Do not send value_type for access_right or usage_limit; it is inferred. *(spec `spec/components/schemas/Create-Feature-Template-Request.yaml`; spec `spec/components/schemas/Feature-Value-Type.yaml`; `maxio-c4:createFeatureTemplate.3`)*
- **silent**, -/side-effects: A feature template is created or updated with wallet_behavior (wallet_product_id, name, price_point_id, depletion_policy, hard_stop_overflow, optional meter_id and conversion_rate), a field the Feature Template reference does not list → Subscriptions that resolve an entitlement to that feature get a wallet provisioned automatically (origin feature). **Do:** Configure wallet_behavior on the feature template to auto-provision wallets; do not call createWallet for that case. Also: `updateFeatureTemplate`. *(docs `content/introduction/basic-concepts/wallets.md`; docs `content/introduction/basic-concepts/wallets.md`; docs `content/introduction/basic-concepts/wallets.md`; `maxio-c4:createFeatureTemplate.7`)*

## `client.FeatureTemplates.ArchiveFeatureTemplate` — `DELETE /features/{id}.json` (`archiveFeatureTemplate`)

- **silent**, -/side-effects: archiveFeatureTemplate is called with remove_from_catalog=true → Every feature catalog item made from the template and their entitlements are destroyed permanently, revoking subscriber access at once; restoring the template does not bring them back. **Do:** Use remove_from_catalog=true only when subscriber access must end now and for good. *(spec `spec/openapi.yaml`; spec `spec/openapi.yaml`; docs `content/introduction/basic-concepts/entitlements.md`; `maxio-c4:archiveFeatureTemplate.1`)*
- **silent**, -/side-effects: A feature template is archived without remove_from_catalog=true → Existing entitlements are kept by default, as with removing a catalog item; remove_from_catalog=true overrides this. **Do:** Pass remove_from_catalog=true when archiving should also revoke the feature. *(docs `content/introduction/basic-concepts/entitlements.md`; `maxio-c4:archiveFeatureTemplate.101`)*
- **silent**, -/side-effects: archiveFeatureTemplate is called without remove_from_catalog (or with false) → The template and its feature catalog items are archived, and existing entitlements are kept. **Do:** Expect current subscribers to keep the feature after a default archive. *(spec `spec/openapi.yaml`; docs `content/introduction/basic-concepts/entitlements.md`; `maxio-c4:archiveFeatureTemplate.2`)*
- **silent**, -/other: A feature template is archived → The template record is never hard-deleted and can always be restored. **Do:** Use restoreFeatureTemplate to bring an archived template back; its key stays taken. *(spec `spec/openapi.yaml`; `maxio-c4:archiveFeatureTemplate.3`)*

## `client.FeatureTemplates.RestoreFeatureTemplate` — `POST /features/{id}/restore.json` (`restoreFeatureTemplate`)

- **silent**, -/side-effects: An archived feature template is restored → Feature catalog items created from the template stay archived. **Do:** Restore each feature catalog item individually after restoring its template. *(spec `spec/openapi.yaml`; `maxio-c4:restoreFeatureTemplate.1`)*
- **silent**, -/side-effects: An archived feature template is restored → Entitlements removed when it was archived are never restored. **Do:** Re-grant removed entitlements yourself after restoring a feature template. *(docs `content/introduction/basic-concepts/entitlements.md`; `maxio-c4:restoreFeatureTemplate.101`)*
