# Wallet Adjustments

## `client.WalletAdjustments.CreateWalletAdjustment` — `POST /wallets/{wallet_id}/adjustments.json` (`createWalletAdjustment`)

- **loud**, state/-: A grant, debit, purchase or adjustment is attempted on an archived wallet → Archiving blocks further grants, debits, purchases and adjustments, but reads and list results are unaffected.. **Do:** Do not write to archived wallets; they remain readable. Also: `archiveWallet`, `createWalletTransaction`, `createWalletPurchase`. *(docs `content/introduction/basic-concepts/wallets.md`; `maxio-c4:archiveWallet.101`)*
- **loud**, -/errors: A wallet amount (initial_balance, conversion_rate, transaction or adjustment amount, purchase quantity) is sent as a JSON number with a decimal point → 422. **Do:** Send fractional wallet amounts as decimal strings (a whole JSON integer is also accepted). Also: `createWallet`, `createWalletTransaction`, `createWalletPurchase`, `previewWalletPurchase`. *(spec `spec/components/schemas/Create-Wallet-Request.yaml`; docs `content/introduction/basic-concepts/wallets.md`; spec `spec/components/schemas/Create-Wallet-Transaction-Request.yaml`; `maxio-c4:createWallet.1`)*
- **loud**, account-config/errors: A wallet endpoint is called on a site without the Wallets feature enabled → 403 "403 Forbidden" The body is plain text, not JSON.. **Do:** Have the Wallets feature enabled for the site and handle a plain-text 403 body. Also: `createWallet`, `createWalletTransaction`, `createWalletPurchase`, `previewWalletPurchase`. *(spec `spec/components/schemas/Create-Wallet-Adjustment-Request.yaml`; spec `spec/components/schemas/Create-Wallet-Purchase-Request.yaml`; spec `spec/openapi.yaml`; `maxio-c4:createWallet.2`)*

- **loud**, state/errors: An overdraft correction exceeds the overdraft the wallet still owes (for example after a later grant repaid it) → 422 "Adjustment exceeds the wallet's outstanding overdraft" The message is followed by how much can still be corrected.. **Do:** Once a later grant has repaid the overdraft, correct that grant's balance instead. *(spec `spec/openapi.yaml`; docs `content/introduction/basic-concepts/wallets.md`; `maxio-c4:createWalletAdjustment.10`)*
- **loud**, state/errors: expected_remaining is sent and no longer matches the grant's current posted_remaining → 409 "The grant balance changed since this correction was prepared. Reload and try again." code grant_changed; nothing is written.. **Do:** On 409, reload the wallet, re-derive the amount and retry. *(spec `spec/components/schemas/Create-Wallet-Adjustment-Request.yaml`; spec `spec/openapi.yaml`; `maxio-c4:createWalletAdjustment.11`)*
- **loud**, account-config/errors: expected_remaining is filled from a grant's remaining (not posted_remaining) on a metered wallet with pending usage → 409. **Do:** Send the grant's posted_remaining as expected_remaining, never remaining. *(spec `spec/openapi.yaml`; docs `content/introduction/basic-concepts/wallets.md`; `maxio-c4:createWalletAdjustment.12`)*
- **loud**, -/errors: expected_remaining or expected_source_corrections is sent as an empty string → 422. **Do:** Leave these fields out entirely to skip the check; never send them empty. *(spec `spec/components/schemas/Create-Wallet-Adjustment-Request.yaml`; spec `spec/openapi.yaml`; `maxio-c4:createWalletAdjustment.14`)*
- **loud**, state/errors: expected_source_corrections is sent with source_transaction_id and no longer matches the sum of corrections posted against that entry → 409 Nothing is written.. **Do:** Send the entry's source_corrections_total as last read, and on 409 reload and retry. *(spec `spec/components/schemas/Create-Wallet-Adjustment-Request.yaml`; spec `spec/openapi.yaml`; `maxio-c4:createWalletAdjustment.15`)*
- **loud**, state/errors: A negative adjustment would take the grant's posted_remaining below zero → 422 "Adjustment exceeds the grant's remaining balance" code adjustment_exceeds_remaining. **Do:** Bound negative adjustments by the grant's posted_remaining; the server rejects rather than clamps. *(spec `spec/components/schemas/Create-Wallet-Adjustment-Request.yaml`; spec `spec/components/schemas/Create-Wallet-Adjustment-Request.yaml`; spec `spec/openapi.yaml`; `maxio-c4:createWalletAdjustment.2`)*
- **loud**, state/errors: A positive adjustment would credit the grant past its original amount → 422. **Do:** Bound positive adjustments by the grant's original minus its posted_remaining. *(spec `spec/components/schemas/Create-Wallet-Adjustment-Request.yaml`; spec `spec/openapi.yaml`; `maxio-c4:createWalletAdjustment.3`)*
- **loud**, other/errors: createWalletAdjustment omits grant_id, or names a grant not on this wallet, while source_transaction_id does not name an overdraft entry → 422. **Do:** Send the grant_id of a grant on this wallet unless correcting an overdraft entry. *(spec `spec/components/schemas/Create-Wallet-Adjustment-Request.yaml`; spec `spec/openapi.yaml`; `maxio-c4:createWalletAdjustment.4`)*
- **loud**, -/errors: createWalletAdjustment sends a grant_id while source_transaction_id names an overdraft entry → 422. **Do:** Omit grant_id when correcting an overdraft entry. *(spec `spec/components/schemas/Create-Wallet-Adjustment-Request.yaml`; spec `spec/openapi.yaml`; `maxio-c4:createWalletAdjustment.5`)*
- **loud**, other/errors: source_transaction_id names a row that is not on this wallet or is not of kind debit → 422. **Do:** Point source_transaction_id only at debit rows of the same wallet; correct grants and adjustments with a further adjustment. *(spec `spec/components/schemas/Create-Wallet-Adjustment-Request.yaml`; spec `spec/openapi.yaml`; `maxio-c4:createWalletAdjustment.6`)*
- **loud**, state/errors: An overdraft correction (no grant_id) is sent with a negative amount → 422 "Overdraft usage can only be corrected downward". **Do:** Send overdraft corrections as positive credits only. *(spec `spec/openapi.yaml`; spec `spec/components/schemas/Create-Wallet-Adjustment-Request.yaml`; `maxio-c4:createWalletAdjustment.8`)*
