# Customers, payment profiles, coupons and offers

- **loud**, state/errors (`client.PaymentProfiles.ChangeSubscriptionDefaultPaymentProfile`, `client.PaymentProfiles.ChangeSubscriptionGroupDefaultPaymentProfile`): The payment profile given is already the current default for the subscription or subscription group → 422 "This is already the current payment profile". **Do:** Compare with the current default before calling, and treat this 422 as no change needed. *(`maxio-c4:changeSubscriptionDefaultPaymentProfile.1`)*
- **loud**, -/errors (`client.Coupons.CreateCoupon`, `client.Coupons.UpdateCoupon`): The coupon code contains characters other than uppercase letters, digits and % @ + - _  → outcome not stated. **Do:** Build coupon codes from uppercase letters, digits and the allowed special characters only. *(`maxio-c4:createCoupon.10`)*
- **loud**, -/errors (`client.Coupons.CreateCoupon`, `client.Coupons.UpdateCoupon`): percentage and amount_in_cents are both sent → outcome not stated. **Do:** Send only one of percentage and amount_in_cents. *(`maxio-c4:createCoupon.3`)*
- **loud**, -/errors (`client.Coupons.CreateCoupon`, `client.Coupons.UpdateCoupon`): allow_negative_balance is set to true together with restricted_products or restricted_components → outcome not stated. **Do:** Do not combine allow_negative_balance with product or component restrictions. *(`maxio-c4:createCoupon.4`)*
- **loud**, -/errors (`client.Coupons.CreateCoupon`, `client.Coupons.UpdateCoupon`): end_date is in the past → 422 "Expiration Date cannot be in the past". **Do:** Send an end_date of today or later, or none. *(`maxio-c4:createCoupon.7`)*
- **loud**, -/errors (`client.Coupons.CreateCoupon`, `client.Coupons.UpdateCoupon`): The coupon amount is negative → 422 "Amount: must be greater than or equal to $0.00.". **Do:** Send a coupon amount of zero or more. *(`maxio-c4:createCoupon.8`)*
- **loud**, limits/errors (`client.Coupons.CreateCoupon`, `client.Coupons.UpdateCoupon`): name, code or description is longer than 255 characters → outcome not stated. **Do:** Keep coupon name, code and description to 255 characters or fewer. *(`maxio-c4:createCoupon.9`)*
- **loud**, -/errors (`client.Customers.CreateCustomer`, `client.Customers.UpdateCustomer`): entity_identifier_kind is vat_eu or national_tax and no vat_country is sent → 422. **Do:** Send vat_country whenever entity_identifier_kind is vat_eu or national_tax. *(`maxio-c4:createCustomer.2`)*
- **loud**, -/errors (`client.Customers.CreateCustomer`, `client.Customers.UpdateCustomer`): vat_country does not fit the identifier kind: vat_eu with a country that is not an EU member state or GB, or national_tax with a country outside AL, AM, AR, AU, BR, CA, CH, DZ, IN, MX, NO, NZ, ZA → 422. **Do:** Check vat_country against the kind's allowed countries before sending the customer. *(`maxio-c4:createCustomer.3`)*
- **loud**, -/errors (`client.Customers.CreateCustomer`, `client.Customers.UpdateCustomer`): entity_identifier_kind is gln, duns or lei and the value is not 13 digits, 9 digits, or 18 letters or digits followed by 2 digits respectively → 422. **Do:** Validate the identifier value's length and characters for gln, duns and lei before sending it. *(`maxio-c4:createCustomer.4`)*
- **loud**, -/errors (`client.Customers.CreateCustomer`, `client.Customers.UpdateCustomer`): entity_identifier_value is sent without entity_identifier_kind while a vat_country is present → 422 "names entity_identifier_kind". **Do:** Send entity_identifier_kind whenever entity_identifier_value is sent. *(`maxio-c4:createCustomer.6`)*
- **loud**, -/errors (`client.PaymentProfiles.CreatePaymentProfile`, `client.PaymentProfiles.UpdatePaymentProfile`): An ACH payment profile has a billing_country other than US → outcome not stated. **Do:** Use billing_country US for ACH bank accounts. *(`maxio-c4:createPaymentProfile.15`)*
- **loud**, order/errors (`client.PaymentProfiles.CreatePaymentProfile`): The chargify_token sent does not match an existing Advanced Billing token → 422 "Advanced Billing token not found". **Do:** Obtain a fresh token from Maxio.js and send it unchanged. *(`maxio-c4:createPaymentProfile.4`)*
- **loud**, other/errors (`client.ReasonCodes.CreateReasonCode`, `client.ReasonCodes.UpdateReasonCode`): A reason code is created or updated with a code another reason code on the site already uses → 422 "Code: This code is already in use.". **Do:** Use a code that no other reason code on the site has. *(`maxio-c4:createReasonCode.1`)*
- **loud**, account-config/- (`client.Coupons.FindCoupon`, `client.Coupons.ValidateCoupon`): The site has more than one product family and the coupon is not in the default (first-created, unarchived) product family, and no product family is given → outcome not stated. **Do:** Pass product_family_id (or the product family in the URL, by id or handle:<handle>) when the coupon may be outside the default family. *(`maxio-c4:findCoupon.1`)*
- **loud**, -/errors (`client.ReasonCodes.ListReasonCodes`, `client.Offers.ListOffers`): page is sent as 0 or a negative number → 422 "invalid page: 0". **Do:** Start paging at page 1. *(`maxio-c4:listReasonCodes.1`)*
- **loud**, order/errors (`client.PaymentProfiles.ReadOneTimeToken`): The chargify_token in the path does not match an Advanced Billing token, which can only be obtained through Chargify.js → 404 "Advanced Billing token not found". **Do:** Obtain the token through Chargify.js before reading it, and treat a 404 as an unknown token. *(`maxio-c4:readOneTimeToken.1`)*
- **loud**, order/errors (`client.BillingPortal.ResendBillingPortalInvitation`): An invitation is resent for a customer that does not exist → 404. **Do:** Treat a 404 as a missing customer, not a transient failure. *(`maxio-c4:resendBillingPortalInvitation.3`)*
- **loud**, order/errors (`client.PaymentProfiles.SendRequestUpdatePaymentEmail`): The request payment update email is requested for a subscription that does not exist → 404. **Do:** Treat a 404 as a missing subscription, not a transient failure. *(`maxio-c4:sendRequestUpdatePaymentEmail.2`)*
- **loud**, account-config/- (`client.PaymentProfiles.UpdatePaymentProfile`, `client.Subscriptions.UpdateSubscription`): The payment profile of a customer who pays taxes is updated → outcome not stated. **Do:** Send complete address information when updating the payment profile of a taxed customer. *(`maxio-c4:updatePaymentProfile.101`)*
- **loud**, order/- (`client.PaymentProfiles.VerifyBankAccount`): Verification is submitted before the customer has received the two small deposits, or with amounts that are not the deposits received → outcome not stated. **Do:** Wait until the customer sees the two deposits in the bank account and submit exactly those amounts in cents. *(`maxio-c4:verifyBankAccount.3`)*
- **silent**, -/values (`client.Coupons.CreateCoupon`, `client.Coupons.UpdateCoupon`): compounding_strategy is set on a coupon that is not stackable → compounding_strategy applies only to stackable coupons. **Do:** Set stackable true when the compounding strategy matters. *(`maxio-c4:createCoupon.11`)*
- **silent**, -/values (`client.Coupons.CreateCoupon`, `client.Coupons.UpdateCoupon`): A stackable percentage coupon is combined with other discounts → With compound the percentage is taken from the price remaining after prior discounts; with full-price it is taken from the original item price. **Do:** Choose compound or full-price deliberately and compute expected totals the same way. *(`maxio-c4:createCoupon.12`)*
- **silent**, -/values (`client.Coupons.CreateCoupon`, `client.Coupons.UpdateCoupon`): allow_negative_balance is true and the discount exceeds the amount billed → The discount is not limited; the excess becomes credit that carries forward to the next billing. **Do:** Set allow_negative_balance only when unused discount should carry forward as credit. *(`maxio-c4:createCoupon.5`)*
- **silent**, -/values (`client.Coupons.CreateCoupon`, `client.Coupons.UpdateCoupon`): A coupon has an end_date → After the end of that day the code is invalid for new signups; recurring discounts started before the date keep recurring after it. **Do:** Do not use end_date to stop discounts already running; it only blocks new signups. *(`maxio-c4:createCoupon.6`)*
- **silent**, -/values (`client.Coupons.CreateCouponSubcodes`, `client.Coupons.UpdateCouponSubcodes`): A subcode in the list is not valid (contains spaces or disallowed characters) → That subcode is not created and is reported among the invalid codes in the response; the rest are processed. **Do:** Check invalid_codes in the response instead of assuming every subcode was created. *(`maxio-c4:createCouponSubcodes.2`)*
- **silent**, -/values (`client.Customers.CreateCustomer`, `client.Customers.UpdateCustomer`): entity_identifier_value is sent with surrounding whitespace or lowercase letters → The value is trimmed and stored in uppercase. **Do:** Compare stored identifiers in trimmed uppercase form, not as originally entered. *(`maxio-c4:createCustomer.10`)*
- **silent**, -/values (`client.Customers.CreateCustomer`, `client.Customers.UpdateCustomer`): An identifier is stored through entity_identifier_kind with kind company_reg, gln, duns or lei → vat_country is set to null. **Do:** Expect vat_country to be null after saving a company_reg, gln, duns or lei identifier, even if one was sent. *(`maxio-c4:createCustomer.11`)*
- **silent**, -/values (`client.Customers.CreateCustomer`, `client.Customers.UpdateCustomer`): organization is omitted, null or an empty string → organization is populated with the customer's first and last name separated by a space. **Do:** Do not treat a returned organization as a real company name unless your app set it. *(`maxio-c4:createCustomer.12`)*
- **silent**, account-config/values (`client.Customers.CreateCustomer`, `client.Customers.UpdateCustomer`): surcharging is sent on a site where surcharging control is not enabled → The value is not applied, and surcharging is not included in the customer response. **Do:** Confirm surcharging control is enabled on the site before relying on the customer's surcharging setting. *(`maxio-c4:createCustomer.14`)*
- **silent**, account-config/- (`client.Customers.CreateCustomer`, `client.Customers.UpdateCustomer`): branding_theme_id is sent on a site where Branding Themes are not enabled → The field is available only when Branding Themes are enabled for the site. **Do:** Send branding_theme_id only on sites with Branding Themes enabled. *(`maxio-c4:createCustomer.15`)*
- **silent**, account-config/side-effects (`client.Customers.CreateCustomer`, `client.Customers.UpdateCustomer`): On a site with Branding Themes enabled, a customer has a branding_theme_id and one of its subscriptions has no subscription-level Branding Theme → The customer's Branding Theme is used for that subscription. **Do:** Expect changing the customer's branding_theme_id to change the branding of every subscription without its own theme. *(`maxio-c4:createCustomer.16`)*
- **silent**, -/values (`client.Customers.CreateCustomer`, `client.Customers.UpdateCustomer`): A vat_number is added or updated on a customer → The number is not validated when saved; it is validated via VIES before taxes are calculated, and only a valid number allows VAT opt-out. **Do:** Validate VAT numbers yourself if you need to catch bad ones at entry; a saved number does not mean VAT opt-out will apply. *(`maxio-c4:createCustomer.17`)*
- **silent**, -/values (`client.Customers.CreateCustomer`, `client.Customers.UpdateCustomer`): tax_exempt is sent as 1 or 0 → 1 is accepted as true and 0 as false. **Do:** Send tax_exempt as true/false or 1/0 only. *(`maxio-c4:createCustomer.18`)*
- **silent**, -/values (`client.Customers.CreateCustomer`, `client.Customers.UpdateCustomer`, `client.PaymentProfiles.CreatePaymentProfile`, `client.PaymentProfiles.UpdatePaymentProfile`, `client.Subscriptions.CreateSubscription`, `client.Subscriptions.UpdateSubscription`): A subscriber is to be taxed but neither the customer nor the payment profile has a full valid address with an ISO 2-3 character state and ISO 2 character country → The subscriber is not eligible to be taxed. **Do:** Send a complete billing or shipping address with ISO state and country codes for every customer who must be taxed. *(`maxio-c4:createCustomer.19`)*
- **silent**, -/values (`client.Customers.CreateCustomer`, `client.Customers.UpdateCustomer`): entity_identifier_value is sent without entity_identifier_kind and no vat_country is present → The value is stored as a company_reg identifier. **Do:** Always send entity_identifier_kind with entity_identifier_value so the kind is not chosen for you. *(`maxio-c4:createCustomer.5`)*
- **silent**, -/values (`client.Customers.CreateCustomer`, `client.Customers.UpdateCustomer`): entity_identifier_kind and entity_identifier_value are both sent blank → The blank pair is ignored rather than rejected or read as a clear; a vat_number sent alongside it still takes effect. **Do:** Do not send a blank pair to clear an identifier; send a supported kind with a blank value instead. *(`maxio-c4:createCustomer.7`)*
- **silent**, -/values (`client.Customers.CreateCustomer`, `client.Customers.UpdateCustomer`): Only the legacy vat_number (and vat_country) is sent, with neither entity identifier field → The kind is derived from vat_country: an EU member state code or GB gives vat_eu, a national tax country code gives national_tax, and a blank or unrecognized country gives company_reg. **Do:** Send vat_country with a legacy vat_number, or send entity_identifier_kind explicitly, so the derived kind is the one you intend. *(`maxio-c4:createCustomer.8`)*
- **silent**, -/values (`client.Customers.CreateCustomer`, `client.Customers.UpdateCustomer`): The customer holds an entity identifier of any kind → The response reports the identifier in entity_identifier_kind and entity_identifier_value and repeats its value in vat_number, whatever its kind. **Do:** Read the identifier's kind from entity_identifier_kind; do not treat vat_number as a VAT number when the kind is not vat_eu. *(`maxio-c4:createCustomer.9`)*
- **silent**, account-config/- (`client.PaymentProfiles.CreatePaymentProfile`, `client.PaymentProfiles.UpdatePaymentProfile`): Billing address fields or a CVV are sent on a payment profile → The values are merely passed through to the payment gateway, which may require its own formats such as specific country codes. **Do:** Format billing address and country values to your gateway's requirements; Advanced Billing does not normalise them. *(`maxio-c4:createPaymentProfile.16`)*
- **silent**, account-config/- (`client.PaymentProfiles.CreatePaymentProfile`, `client.PaymentProfiles.UpdatePaymentProfile`, `client.Subscriptions.CreateSubscription`): current_vault is sent with a value that does not match a gateway configured for the site, such as stripe instead of stripe_connect → The value is not currently validated against the site's gateways; that validation was briefly applied, reverted, and is to be re-introduced. **Do:** Send the current_vault value that matches the site's configured gateway so the request keeps working when validation returns. *(`maxio-c4:createPaymentProfile.19`)*
- **silent**, -/values (`client.BillingPortal.EnableBillingPortalForCustomer`, `client.BillingPortal.ReadBillingPortalLink`): A Management URL is issued for a customer → The URL changes periodically for security and is valid for only 65 days. **Do:** Store the URL with its expires_at and fetch a new one before it expires rather than keeping it indefinitely. *(`maxio-c4:enableBillingPortalForCustomer.4`)*
- **silent**, account-config/values (`client.Coupons.ListCouponsForProductFamily`, `client.Coupons.ListCoupons`, `client.Coupons.FindCoupon`, `client.Coupons.ReadCoupon`): currency_prices=true is sent on a site with multiple currencies defined → Each coupon includes an array of currency price data; without the parameter it is not returned. **Do:** Send currency_prices=true when you need per-currency coupon amounts. *(`maxio-c4:listCouponsForProductFamily.1`)*
- **silent**, -/lists (`client.Coupons.ListCouponsForProductFamily`, `client.Coupons.ListCoupons`): filter[use_site_exchange_rate] is sent → true returns only coupons priced from the site's current exchange rates (on-the-fly currency_prices); false returns only coupons with manually defined amounts per currency (stored currency_prices). **Do:** Omit the filter to get both kinds of coupons. *(`maxio-c4:listCouponsForProductFamily.2`)*
- **silent**, account-config/values (`client.Customers.ListCustomers`, `client.Coupons.ListCoupons`, `client.Coupons.ListCouponsForProductFamily`): start_date or end_date (date only) is sent to filter by date_field → start_date matches records at or after midnight and end_date matches records up to and including 11:59:59 PM, both in the site's time zone. **Do:** Convert date filters to the site's time zone, or use start_datetime/end_datetime with an explicit offset. *(`maxio-c4:listCustomers.3`)*
- **silent**, limits/lists (`client.Customers.ListCustomers`, `client.Coupons.ListCouponsForProductFamily`, `client.Coupons.ListCoupons`, `client.Coupons.ListCouponSubcodes`, `client.Offers.ListOffers`, `client.PaymentProfiles.ListPaymentProfiles`, `client.ReasonCodes.ListReasonCodes`): per_page is sent above 200 → per_page is changed to 200. **Do:** Page with per_page of at most 200 and expect no more than 200 records per page. *(`maxio-c4:listCustomers.7`)*
- **silent**, -/lists (`client.Customers.ListCustomers`, `client.Coupons.ListCouponsForProductFamily`, `client.Coupons.ListCoupons`, `client.Coupons.ListCouponSubcodes`, `client.Offers.ListOffers`, `client.PaymentProfiles.ListPaymentProfiles`, `client.ReasonCodes.ListReasonCodes`): page asks for a page past the last page of results → An empty result set is returned. **Do:** Stop paging when a page comes back empty. *(`maxio-c4:listCustomers.8`)*
- **silent**, -/lists (`client.ReasonCodes.ListReasonCodes`, `client.ReasonCodes.CreateReasonCode`, `client.ReasonCodes.UpdateReasonCode`): Reason codes are listed or shown → Codes appear in the order given by their position. **Do:** Set position on each reason code to control the order in which it appears. *(`maxio-c4:listReasonCodes.2`)*
- **silent**, -/lists (`client.Customers.ReadCustomerByReference`, `client.Customers.ListCustomers`): A customer is looked up by its reference → The lookup endpoint returns a single exact match, while the list search with q returns an array of customers matching the query. **Do:** Use the lookup endpoint, not the q search, when you need the one customer with an exact reference. *(`maxio-c4:readCustomerByReference.1`)*
- **silent**, account-config/values (`client.Offers.ReadOffer`, `client.Offers.ListOffers`, `client.Offers.CreateOffer`): An offer is returned from a site without Multifrequency enabled → The offer items' interval and interval_unit properties are only available on sites with Multifrequency enabled. **Do:** Treat offer item interval and interval_unit as optional and absent unless the site has Multifrequency. *(`maxio-c4:readOffer.1`)*
- **silent**, account-config/- (`client.PaymentProfiles.ReadOneTimeToken`, `client.PaymentProfiles.CreatePaymentProfile`): A one-time token is used for ACH (bank account) data on a gateway other than Authorize.Net or Stripe → One-time tokens hold ACH data only for Authorize.Net or Stripe. **Do:** Use one-time tokens for ACH only on Authorize.Net or Stripe sites. *(`maxio-c4:readOneTimeToken.2`)*
- **silent**, other/- (`client.BillingPortal.ResendBillingPortalInvitation`, `client.BillingPortal.RevokeBillingPortalAccess`): The invitation resend or revoke endpoint is called with a non-JSON format → The endpoint only returns a JSON response. **Do:** Call these endpoints with the .json format and parse JSON. *(`maxio-c4:resendBillingPortalInvitation.4`)*
- **silent**, -/webhooks (`client.PaymentProfiles.UpdatePaymentProfile`, `client.PaymentProfiles.ChangeSubscriptionDefaultPaymentProfile`, `client.PaymentProfiles.DeleteSubscriptionsPaymentProfile`): A subscription's active credit-card-type payment profile changes, including a partial card or billing address update or the deletion of a PayPal profile → A subscription_card_update webhook is sent with the previous and updated payment profiles. **Do:** Listen for subscription_card_update to keep stored card details in sync. *(`maxio-c4:updatePaymentProfile.6`)*
