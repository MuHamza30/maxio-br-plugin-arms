# Background: renewal

- **silent**, state/side-effects (`background:renewal`): A subscription with automatic payment collection renews → The customer is charged automatically. **Do:** Keep a valid payment method on automatic subscriptions before renewal. *(`maxio-c4:background.59`)*
- **silent**, state/side-effects (`background:renewal`): A subscription with remittance collection renews → The customer is not charged; an invoice is generated, and payment is recorded manually once received. **Do:** Record remittance payments yourself when they arrive. *(`maxio-c4:background.60`)*
- **silent**, -/side-effects (`background:renewal`): A subscription group renews → Payment success and failure events are created for the primary subscription, as at signup. **Do:** Track group renewal payments through the primary subscription's events. *(`maxio-c4:background.64`)*
- **silent**, -/values (`background:renewal`, `client.Components.CreateMeteredComponent`, `client.Components.CreateQuantityBasedComponent`): A billing period ends for a subscription with metered and quantity-based components → Metered component usage resets to 0; quantity-based allocations do not reset. **Do:** Report metered usage per period and do not re-allocate quantity components each period. *(`maxio-c4:background.65`)*
- **silent**, state/values (`background:renewal`, `client.SubscriptionComponents.ActivateEventBasedComponent`, `client.SubscriptionComponents.DeactivateEventBasedComponent`): A subscription renews with an event-based component → Event usage is billed only if the component is activated for the subscription; events of a deactivated component are ignored at renewal, although events can be streamed at any time. **Do:** Activate the event-based component for each subscription that should be billed for its events. *(`maxio-c4:background.66`)*
- **silent**, order/side-effects (`background:renewal`, `client.Subscriptions.UpdateSubscription`): A delayed product change (product_change_delayed=true) is set on a subscription → The product change happens automatically at the next renewal date, with no proration; setting next_product_id to an empty string cancels it. **Do:** Expect the new product only from the next renewal and cancel with an empty next_product_id if needed. *(`maxio-c4:background.67`)*
- **silent**, order/side-effects (`background:renewal`, `client.SubscriptionStatus.InitiateDelayedCancellation`, `client.SubscriptionStatus.CancelSubscription`, `client.SubscriptionStatus.CancelDelayedCancellation`): A delayed cancellation is set on a subscription → The subscription is canceled at the end of the current billing period, unless the delayed cancellation is removed first. **Do:** Remove the delayed cancellation before the period ends if the customer stays. *(`maxio-c4:background.68`)*
- **silent**, state/side-effects (`background:renewal`, `client.SubscriptionStatus.PauseSubscription`, `client.SubscriptionStatus.UpdateAutomaticSubscriptionResumption`): A subscription is on hold → It does not renew, and it resumes automatically on automatically_resume_at when that date is set. **Do:** Set or clear automatically_resume_at to control when a held subscription resumes. *(`maxio-c4:background.69`)*
